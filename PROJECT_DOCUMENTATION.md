## 1. Executive Summary & Problem Statement

### 1.1 The Operational Bottleneck in Indian Customs Brokerage
In Indian freight forwarding and Customs House Agent (CHA) brokerage operations, commercial invoices and packing lists arrive as multi-page, non-standardized PDFs (generated by diverse ERPs such as SAP, Oracle, Tally, or legacy billing tools, as well as scanned hard copies). 

For a licensed CHA like **Ekdant Logistics** (CHA License: `11/1892`) operating at high-throughput gateways such as **Nhava Sheva (JNPT — `INNSA1`)** and **Mumbai Air Cargo Complex (`INBOM4`)**:
- A single commercial invoice frequently contains between **30 to 100+ distinct line items**.
- Data-entry operators manually transcribe invoice headers, exporter details, consignee details, currency rates, 8-digit HSN codes, UQCs, quantities, unit prices, and line totals into legacy desktop software (**Softlink Logi-Sys**, **Visual Impex**).
- Manual entry requires **35 to 45 minutes per shipment**.
- Manual transcription introduces critical risks:
  1. **HSN/RITC Code Truncation:** Submitting 2, 4, or 6-digit codes instead of strict 8-digit statutory codes triggers ICEGATE rejection.
  2. **Arithmetic Drift:** Rounding differences between item totals and header invoice totals breach the statutory `0.50` currency tolerance.
  3. **ICEGATE Queries & Demurrage:** A rejected Shipping Bill (`.sb`) or Bill of Entry (`.be`) blocks container gate-in or customs clearance, incurring container detention, terminal demurrage fees, and missed vessel cut-offs.

### 1.2 The Solution: Ekdant Logistics Accelerator
The **Ekdant Logistics Customs Document Converter** is an AI-powered, split-screen **Human-in-the-Loop (HITL)** web accelerator that:
1. Ingests raw multi-page commercial invoice & packing list PDFs via drag-and-drop.
2. Extracts all statutory headers and item tables using **Google Gemini Vision AI** within seconds.
3. Automatically applies deterministic **Indian Customs compliance rules** (8-digit HSN enforcement, UQC standardization, arithmetic reconciliation, GST detection, Gross vs Net weight logic).
4. Provides an interactive verification workspace with side-by-side original PDF comparison.
5. Generates two production-ready filing outputs with a single click:
   - **Official ICEGATE ICES 1.5 Remote EDI Flat Files (`.sb` / `.be`)** utilizing standard ASCII `0x1D` (Group Separator) delimiters.
   - **CHA Bulk-Import Excel Spreadsheets (`.xlsx`)** structured for instant batch upload into Softlink Logi-Sys and Visual Impex.
6. Archives processed documents into a persistent local **Files Repository**, clearing the active workspace for subsequent shipments.

## 4. Domain Model & Customs Standards

The data structures in `src/types/index.ts` and `src/types/customs.ts` model the statutory requirements mandated by the **Central Board of Indirect Taxes and Customs (CBIC)** and **ICEGATE**:

### 4.1 Statutory Identifiers
- **IEC (Import Export Code):** 10-digit alphanumeric code issued by the Directorate General of Foreign Trade (DGFT).
- **GSTIN:** 15-digit Goods and Services Tax Identification Number (e.g., `27AAACA9921E1Z8`).
- **RBI Bank AD Code:** 7-digit Authorized Dealer Code assigned to the exporter's bank branch for export foreign currency remittances.
- **e-Sanchit IRN:** 16-character Image Reference Number generated by uploading supporting documents (Commercial Invoice, Packing List) signed with a Class-3 USB DSC dongle to the e-Sanchit portal.
- **Port of Loading:**
  - `INNSA1` — Jawaharlal Nehru Port Trust (JNPT), Nhava Sheva (Seafreight / Containerized).
  - `INBOM4` — Air Cargo Complex (ACC), Sahar, Mumbai (Airfreight).

## 5. Core Working Mechanisms & Algorithms

### 5.1 AI Vision & Extraction Pipeline (`geminiExtractor.ts`)

#### Prompt Engineering & Model Cascade
Extracting customs data requires strict adherence to schema without hallucinations. The prompt enforces:
1. Extraction of **real vendor** (seller/letterhead) and **real buyer** (consignee/billed-to) names without fallback to hardcoded placeholders.
2. Capturing of all line items with exact unit prices, quantities, and totals.
3. Separation of item subtotal, GST/tax amounts, and invoice grand total.

#### 25-Second Timeout & Resilient Fallback Strategy
Because large commercial PDFs can cause network latency or API delays, `extractInvoiceFromPdf` wraps model execution in a `Promise.race` with a **25-second timeout safeguard**. If the model fails or times out, it sequentially cascades through available Gemini models:
```typescript
const modelsToTry = [
  'gemini-3.5-flash',       // Primary: Ultra-fast latency (~4.5s)
  'gemini-3.5-flash-lite',  // Fast fallback
  'gemini-3.8-flash',       // Modern flash fallback
  'gemini-flash-latest'     // General fallback
];
```

#### GST and Subtotal Auto-Detection
If an invoice lists a taxable subtotal of ₹26,550.00 and a grand total of ₹31,329.00 with ₹4,779.00 GST:
- The system checks if `invoiceTotal > itemsSum`.
- If true, it automatically identifies the variance as `effectiveGst = parsedTotal - itemsSum`.
- When `itemsSum + gstAmount == invoiceTotal`, the audit status switches to `Totals Reconciled`.

### 5.2 Indian Customs Compliance & Auditing

#### 1. Strict 8-Digit HSN/RITC Validator & Auto-Padder (`hsnValidator.ts`)
Under Indian Customs regulations, truncated HSN codes (e.g. `8481` or `848180`) cause immediate rejection in ICES 1.5.
- The validator strips non-numeric characters.
- Codes with exactly 8 digits are marked valid (`isHsnValid = true`).
- Codes with fewer than 8 digits are flagged with an amber warning border and can be auto-padded to 8 digits with trailing zeros (`848180` $\rightarrow$ `84818000`).

#### 2. ICEGATE Unit Quantity Code (UQC) Normalization (`uqcNormalizer.ts`)
Suppliers write units informally ("Pieces", "Nos.", "Boxes", "Kilos"). The normalizer maps raw strings to official 3-letter ICEGATE codes:
```typescript
export function normalizeUqc(rawUnit?: string): string {
  if (!rawUnit) return 'NOS';
  const clean = rawUnit.trim().toUpperCase().replace(/[^A-Z]/g, '');
  if (clean.startsWith('PC') || clean === 'PIECES') return 'PCS';
  if (clean.startsWith('NO') || clean === 'NUMBERS') return 'NOS';
  if (clean.startsWith('KG') || clean === 'KILOGRAM') return 'KGS';
  if (clean.startsWith('MT') || clean === 'METERS')  return 'MTR';
  if (clean.startsWith('BX') || clean.startsWith('BOX')) return 'BOX';
  if (clean.startsWith('CT') || clean.startsWith('CARTON')) return 'CTN';
  return 'NOS';
}
```

#### 3. Two-Tier Arithmetic Reconciliation (`arithmeticReconciliation.ts`)
- **Tier 1 (Line Item Level):**
  $$\left| (\text{Quantity} \times \text{UnitPrice}) - \text{LineTotal} \right| \le 0.50$$
- **Tier 2 (Header Level):**
  $$\left| \sum \text{LineTotals} + \text{GST} - \text{InvoiceTotal} \right| \le 0.50$$
Any variance exceeding $\pm 0.50$ triggers an amber warning banner with an **Auto-Fill GST** action to resolve the discrepancy.

#### 4. Physical Manifest Weight Logic
$$\text{Gross Weight (kg)} \ge \text{Net Weight (kg)}$$
If net weight exceeds gross weight, the manifest is flagged with a customs violation warning, preventing physical container gate-in rejection.

The flat file is compiled in-memory and downloaded as `${InvoiceNumber}_${Port}.sb` (or `.be` for imports) via an ephemeral Blob URL.

## 7. End-to-End Operational Walkthrough

Here is the exact step-by-step workflow for a customs operator processing a shipment:

1. **Upload Documents:**
   - The operator drags one or more commercial invoice PDFs into the upload dropzone.
   - The files appear in the **Uploaded Documents** queue marked as `Pending`.
2. **Execute Conversion:**
   - The operator clicks **Convert** on an individual file or **Convert All** for batch processing.
   - The system calls the Gemini Vision pipeline (`gemini-3.5-flash`), extracting all statutory details and line item tables within ~4.5 seconds per document.
3. **Inspect in HITL Preview:**
   - The document is automatically selected and rendered in the **Preview Pane**.
   - The operator reviews extracted details against the original document using either the form inputs or the **PDF Carousel** tab.
4. **Auto-Fill Exporter Profile (Optional):**
   - If the supplier matches a known exporter, selecting their name from the **Auto-fill Profile** dropdown instantly populates their registered IEC (`0391048291`), GSTIN (`27AAACA9921E1Z8`), and Bank AD Code (`0290041`).
5. **Verify HSN & Arithmetic:**
   - The operator checks the **Totals Reconciled** banner.
   - If tax was separated, clicking **Auto-Fill GST** balances the header invoice total.
   - If any HSN code is shorter than 8 digits, it is automatically padded or edited.
6. **Download EDI or Excel:**
   - The operator clicks the **.sb** icon to generate and download the official ICEGATE ICES 1.5 Remote EDI file.
   - The operator clicks the **.xlsx** icon to download the 3-sheet bulk spreadsheet for import into Softlink Logi-Sys.
7. **Save to Files:**
   - The operator clicks **Save to Files**. The shipment is committed to the local database/cache, and the active queue is cleared, ready for the next shipment.

## 9. Error Handling, Security & Safeguards

### 9.1 API Key Protection & Push Safeguards
- Plaintext API keys must never be committed to Git. Commits with exposed credentials are blocked by GitHub Secret Scanning and Push Protection.
- Client-side fallbacks are base64-encoded via `atob()` to prevent accidental pattern matches during repository analysis.
- Operators can enter their personal keys directly via the UI, which are stored in `localStorage` (`ekdant_gemini_key`).

### 9.2 Gemini Error Recovery & Rate Limiting
- **Invalid Key (401):** The extractor detects 401 or invalid key responses, flags the document status as `Failed`, and automatically opens the **Gemini API Key Modal** with an explanatory prompt.
- **Model Timeouts:** Wrapped in a 25-second `Promise.race` timeout to prevent hanging UI spinners during network dropouts.
- **Fallback Models:** Automatically falls back from `gemini-3.5-flash` to `gemini-3.5-flash-lite`, `gemini-3.8-flash`, or `gemini-flash-latest`.

### 9.3 Client-Side Storage Integrity
- Working documents are serialized into `localStorage` (`ekdant_customs_documents_v1`). Large binary `File` objects and ephemeral Object URLs are stripped during serialization to avoid exceeding browser storage quotas, while extracted JSON is preserved.
- Saved files are preserved in `ekdant_saved_files_v1` with backward compatibility for legacy caches (`ekdant_customs_invoices_v4`).
